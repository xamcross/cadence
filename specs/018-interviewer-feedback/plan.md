# Implementation Plan: Interviewer Feedback Forms & Reminder Escalation (F32)

**Branch**: `018-interviewer-feedback` | **Date**: 2026-06-17 | **Spec**: [spec.md](./spec.md)
**Input**: Feature specification from `/specs/018-interviewer-feedback/spec.md`

## Summary

F32 closes the feedback-to-decision loop: after an interview occurs, every panel interviewer gets a private **no-login** link to a short structured scorecard; if they don't submit by the workspace deadline, Cadence sends **escalating reminder emails** until they do; Recruiters/Admins see who responded and read the scorecards (backlog F32, Tier 2 P2; constitution §I "Interviewer feedback forms — structured scorecard with reminder escalation"). Voice-to-scorecard is deferred to v1.5.

Like F13/F23/F30/F31, F32 is **mostly orchestration of existing seams**: **no new runtime dependency, no broker, one new collection** (`feedbackRequests`, whose `{interviewEventId, submittedAt}` index was already pre-created by `ChangeUnit001`/F00.1), and **one Mongock changeset** (`ChangeUnit017`, order "017" off the highest applied "016"). Reuse verified against real source:

- **The booked-interview record + participant snapshot exist**: `SchedulingRequest` (`status=BOOKED`, denormalized `bookedStartAt` from F23) is the interview occurrence; the panel interviewers are the **ACTIVE `InterviewSlotClaim`** rows (`SlotReservationService.participantsFromClaims` reads `findByWorkspaceIdAndSchedulingRequestId` filtered to `ClaimStatus.ACTIVE`). Cancel/reschedule already flip the request to `CANCELLED`/`RESCHEDULED` and `releaseClaims(...)`, so a non-occurrence is excluded by construction (FR-006).
- **The scheduler pattern exists**: `NoShowDefenseScheduler` (own `TASK_NAME`, `@PostConstruct registerReplayAction`, `@Scheduled(fixedDelayString)`, `checkpoints.start/complete`, per-workspace cache, `Pageable`-bounded `@Query` finders) is the exact template for `FeedbackScheduler` (checkpoint `"feedback-scan"`).
- **The member-mail path exists**: interviewer emails are **operational member mail** via `EmailSender.sendEmail(toInternalId, templateId, mergeFields)` → `SmtpEmailSender`'s closed `if/else` dispatcher (the F13 `INTERVIEW_CONFIRMATION_ID` branch is the precedent) + `OperationalEmailTemplates` `{key}` substitution. **This is NOT the candidate consent-gated `EmailDispatchService`** — the recipient is a workspace member, so the candidate consent/erasure email gate does not apply (FR-004). F32 adds two operational templates + two `sendEmail` branches.
- **The token / no-login / rate-limit chain exists**: `SecureTokens.newToken()` (256-bit), `TokenHasher.hashToken` (HMAC), the F30 `findBy…TokenHash` + STATUS-before-TIME resolution, `CandidateRateLimiter.tryAcquire(ip)` (hashed-IP keyed), and the `@Order(2)` `securityMatcher("/api/public/**","/api/candidate/**")` permitAll/STATELESS/CSRF-disabled chain — F32 adds `/api/feedback/**` to that matcher.
- **The erasure/PII/audit seams exist**: `CandidateErasureService.wipe` (single guarded `updateFirst` + `supersedeLiveScheduling` + the narrow `slaDraftInvalidator` cycle-break precedent), `MongoPiiConfig` per-field converter registration (encrypt the scorecard free text the F13 `locationText` way), `CandidateAuditService`, `RecruiterNotificationService.notify`, `DeadLetterService.recordFailure` (PII-sanitising).

**Two load-bearing design decisions (research D2, D8):**

1. **"Interview occurred" detection reuses `SchedulingRequest` + one new stamp `feedbackGeneratedAt`** (the F23 stamp precedent — `confirmationRequestedAt`/`escalatedAt`/`noShowAt` are the model). The generation finder `status=BOOKED AND feedbackGeneratedAt=null AND bookedStartAt <= now − generationDelay` reuses the existing **`{status, bookedStartAt}`** index (`ChangeUnit014`/F23) — **no new `candidates`/`schedulingRequests` index for the scan**. A single CAS `{_id, status:BOOKED, feedbackGeneratedAt:null} → set feedbackGeneratedAt=now` makes generation fire exactly once per occurrence across overlapping sweeps; then one `feedbackRequests` row is fanned out per ACTIVE participant. `bookedEndAt` is **not** denormalized (only `bookedStartAt` + the in-memory chosen-slot end), so the spec's "interview end + 24h" is anchored on `bookedStartAt + generationDelay` (a configurable post-interview offset) — documented honestly in research D2/D7.
2. **The `feedbackRequests` row IS the scorecard** (one collection, not two): the request carries the hashed token + reminder-escalation state + lifecycle, and the submission populates an **encrypted `scorecardPayload`** field + `submittedAt`. This matches the pre-declared `{interviewEventId, submittedAt}` index (submittedAt null ⇒ pending) and keeps the PII surface to one encrypted field cleared on erasure.

The §II demonstrable leg: a **public no-login scorecard page** at `/feedback?token=…` (interviewer-facing, mobile-first — so unlike F31 the **WCAG 2.2 AA / Lighthouse §IX gates APPLY** here, the F13/F14/F30 precedent) submits a scorecard browser→DB; the scheduled `FeedbackScheduler` sends the request + escalating reminders via real member mail (stub/real transport); a recruiter-internal panel on the existing `/scheduling` view (internal screen — Lighthouse/WCAG N/A) shows per-interview submission status and reads scorecards.

## Multi-role plan review (2026-06-17) — verdict: CHANGES-NEEDED → fixed (re-check PASS)

Reviewers: Backend/Architecture, Security/GDPR, QA/DevOps — each verified claims against the **real source**. Two BLOCKERs + several SHOULD-FIXes, all folded into the artifacts before `tasks.md`:
